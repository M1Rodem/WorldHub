# WorldHub

WorldHub — система для совместной игры в Minecraft без постоянного игрового сервера.

Проект объединяет desktop-приложение и Minecraft Forge-мод. WorldHub позволяет регистрировать Minecraft-миры, создавать их версии, хранить историю изменений, восстанавливать предыдущие версии и организовывать обмен мирами между игроками.

WorldHub не является Minecraft-сервером. Во время совместной игры Minecraft продолжает использовать собственные механизмы LAN, а сетевое взаимодействие между экземплярами WorldHub используется для обмена данными о мирах и их версиях.

---

## Основная идея

WorldHub использует модель работы с мирами, частично похожую на Git/GitHub:

* Minecraft-мир является рабочим состоянием;
* после игровой сессии создаётся Snapshot — зафиксированная версия мира;
* несколько последних версий хранятся локально;
* версии можно просматривать и восстанавливать;
* в дальнейшем Snapshot может передаваться другому игроку;
* другой игрок получает копию мира и продолжает игру;
* после следующей игровой сессии создаётся новая версия.

Таким образом, игрокам не требуется постоянно держать отдельный Minecraft-сервер.

---

## Как работает WorldHub

WorldHub состоит из нескольких частей:

```text
Minecraft
    │
    ▼
WorldHub Minecraft Mod
    │
    │ локальное соединение
    ▼
WorldHub App
    │
    ├── World
    ├── Snapshot
    ├── History
    ├── Restore
    │
    └── Network
            │
            │ TCP / Radmin VPN
            ▼
      WorldHub другого игрока
```

### Совместная игра

Для совместной игры Minecraft использует LAN.

Сетевое соединение между компьютерами может проходить через:

* Radmin VPN;
* Hamachi;
* другую сеть, обеспечивающую доступ между компьютерами.

WorldHub при этом не заменяет Minecraft LAN и не выступает игровым сервером.

---

## Основной сценарий

MVP рассчитан на двух игроков.

### Первый игрок

1. Запускает WorldHub.
2. Регистрирует Minecraft-мир.
3. Запускает Minecraft.
4. Играет вместе со вторым игроком.
5. После завершения игровой сессии WorldHub получает уведомление от Minecraft-мода.
6. WorldHub создаёт Snapshot текущего состояния мира.
7. Snapshot становится новой версией мира.

### Второй игрок

1. Подключается к Minecraft-миру первого игрока.
2. Играет вместе с ним.
3. После получения новой версии мира в дальнейшем может продолжить игру уже со своей копией.
4. После завершения своей игровой сессии создаёт следующую версию.
5. Версия может быть передана обратно первому игроку.

Цикл может продолжаться:

```text
Игрок A
   │
   │ играет
   ▼
Snapshot A1
   │
   │ передача
   ▼
Игрок B
   │
   │ играет
   ▼
Snapshot B1
   │
   │ передача
   ▼
Игрок A
   │
   ▼
Snapshot A2
```

# Возможности

## Управление мирами

WorldHub позволяет:

* добавлять Minecraft-мир в приложение;
* предотвращать повторную регистрацию одного и того же мира;
* хранить информацию о зарегистрированных мирах;
* просматривать состояние мира;
* удалять регистрацию мира из WorldHub;
* сохранять физические файлы Minecraft-миров при удалении их регистрации.

Удаление мира из WorldHub не означает автоматическое удаление самого Minecraft save.

---

## Snapshot и версии

После завершения игровой сессии WorldHub может создавать Snapshot мира.

Snapshot содержит зафиксированное состояние Minecraft-миров и используется как версия, с которой в дальнейшем можно работать.

Для каждого мира локально хранится не более **трёх последних Snapshot**.

При создании новой версии:

```text
Snapshot 1
Snapshot 2
Snapshot 3
```

Если появляется новая версия:

```text
Snapshot 2
Snapshot 3
Snapshot 4
```

Самая старая версия удаляется вместе с соответствующими физическими файлами.

Это позволяет ограничивать использование дискового пространства.

---

## История

Для зарегистрированного мира WorldHub хранит историю Snapshot.

В интерфейсе можно:

* просматривать версии;
* видеть текущую версию;
* выбирать Snapshot;
* восстанавливать состояние мира из выбранной версии.

История учитывает политику хранения последних трёх Snapshot.

---

## Восстановление мира

WorldHub поддерживает восстановление Minecraft-миров из сохранённых Snapshot.

Восстановление выполняется через отдельную логику восстановления, чтобы операция не зависела от UI-компонентов.

Перед использованием восстановления рекомендуется убедиться, что Minecraft не использует соответствующий мир.

---

# Сетевое взаимодействие

WorldHub содержит собственный сетевой слой для связи между экземплярами приложения.

Сейчас используется TCP.

Архитектура сетевого слоя разделена на:

```text
WorldHub.Network
├── Interfaces
├── Models
├── Protocol
├── Providers
└── Services
```

Основные компоненты:

* `INetworkProvider` — абстракция сетевого провайдера;
* `TcpNetworkProvider` — TCP-реализация;
* `NetworkConnection` — сетевое соединение;
* `NetworkListener` — ожидание входящих соединений;
* `NetworkHandshake` — первоначальное подтверждение WorldHub;
* `NetworkService` — работа с подключениями;
* `TcpTransferTransport` — транспорт потоковой передачи данных.

---

## Подключение WorldHub

Каждый экземпляр WorldHub имеет сетевой порт.

В интерфейсе подключения отображается адрес текущего WorldHub:

```text
26.x.x.x:PORT
```

где `26.x.x.x` — адрес компьютера в Radmin VPN.

Другой игрок указывает:

```text
IP-адрес друга
Порт WorldHub друга
```

После этого WorldHub выполняет TCP-подключение и handshake.

Протокол начального соединения использует сообщения:

```text
WORLDHUB_HELLO
WORLDHUB_READY
```

После успешного handshake WorldHub подтверждает возможность связи.

---

## Локальное тестирование сети

Сетевое взаимодействие можно тестировать на одном компьютере, запустив два экземпляра WorldHub на разных портах.

Например:

```text
WorldHub A
Network: 27072
Mod:     27071

WorldHub B
Network: 27074
Mod:     27073
```

После запуска второй экземпляр может подключиться к:

```text
127.0.0.1:27072
```

и выполнить handshake.

Такой режим используется для проверки сетевого слоя до проведения тестов между двумя физическими компьютерами.

# Minecraft Mod

`WorldHub.Minecraft` — Forge-мод, обеспечивающий интеграцию Minecraft с WorldHub.

Мод отвечает за связь Minecraft с desktop-приложением.

Основные компоненты:

```text
WorldHub.Minecraft
├── WorldHubMod.java
├── connection
│   └── WorldHubConnection.java
├── events
│   └── WorldHubForgeEvents.java
├── network
│   └── WorldHubClient.java
└── session
    └── WorldSession.java
```

---

## Связь Minecraft и WorldHub

Minecraft-мод устанавливает локальное TCP-соединение с WorldHub.

При подключении используется handshake:

```text
WORLDHUB_HELLO
        ↓
WORLDHUB_READY
```

После завершения игровой сессии мод сообщает WorldHub:

```text
SESSION_ENDED|sessionId|worldName|worldPath
```

WorldHub получает эту информацию и запускает обработку завершённой игровой сессии.

На текущем этапе это используется, в частности, для автоматического создания Snapshot.

# Передача миров

Архитектура WorldHub предусматривает передачу Snapshot между экземплярами приложения.

Для этого существуют:

* `Transfer`;
* направления передачи;
* состояния передачи;
* сетевой транспорт;
* потоковая передача данных.

Планируемая схема:

```text
WorldHub A
    │
    │ Snapshot
    ▼
Network
    │
    ▼
WorldHub B
    │
    ▼
Local Snapshot
    │
    ▼
Minecraft World
```

На текущем этапе базовый сетевой handshake уже работает, а полноценный пользовательский Push/Pull-процесс и реальный обмен мирами между двумя компьютерами находятся в разработке.

---

# Безопасность и ограничения сети

WorldHub рассчитан на использование в доверенной сети между игроками.

Для первоначального MVP предполагается использование VPN-сетей вроде:

* Radmin VPN;
* Hamachi.

Это позволяет компьютерам находиться в одной виртуальной сети и обращаться друг к другу по IP-адресам VPN.

На текущем этапе проект не является полноценной системой с:

* облачной авторизацией;
* аккаунтами;
* системой друзей;
* NAT traversal;
* собственным relay-сервером;
* публичной инфраструктурой передачи данных.

Эти возможности не являются частью текущего MVP.

---

# Хранение Snapshot

WorldHub хранит Snapshot локально.

Для каждого мира действует ограничение:

```text
MAX SNAPSHOTS = 3
```

Система автоматически удаляет более старые версии после превышения лимита.

Это позволяет:

* ограничивать размер локального хранилища;
* сохранять историю последних изменений;
* не накапливать неограниченное количество копий мира.

# Принцип работы с миром

WorldHub не синхронизирует Minecraft-мир в реальном времени.

Во время игры используется обычная Minecraft-сессия.

WorldHub работает с версиями мира **между игровыми сессиями**:

```text
Игра
 ↓
Завершение сессии
 ↓
Snapshot
 ↓
Передача
 ↓
Получение Snapshot
 ↓
Продолжение игры
 ↓
Новый Snapshot
```

Это позволяет отделить:

* игровое сетевое взаимодействие Minecraft;
* управление версиями;
* передачу сохранений;
* историю изменений.

# Цель проекта

Основная цель WorldHub — предоставить простой способ совместной игры в Minecraft, при котором игроки могут передавать актуальное состояние мира друг другу без необходимости постоянно поддерживать отдельный Minecraft-сервер.

Вместо постоянного сервера используется модель:

```text
Minecraft LAN
      +
WorldHub
      +
Snapshots
      +
Передача версий
```

WorldHub должен обеспечить последовательную передачу состояния мира между игроками и возможность продолжения игры с актуальной версии.
